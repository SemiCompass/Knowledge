# 階層要求の確認・回答収集ツール（HTML）

- **用途**: 階層化された要求（上位要求→システム要求→構成要素への要求）のつながりを見せ、構成要素の担当者に確認を依頼して回答を集める、汎用の単一ファイルHTMLツールを作らせる
- **使う場面**: 要求の割り付け（アロケーション）を各担当に確認してもらい、回答をCSVで集計したいとき。題材は自動車・医療機器・業務システム・設備など何でもよい
- **カテゴリー**: ツール作成 ／ HTMLツール
- **更新日**: 2026-11-27

## プロンプト

```
#依頼
階層化された要求（上位要求＋システム要求・構成要素への要求）のつながりを見せ、構成要素の担当者に要求の確認を依頼して回答を集める、汎用のHTMLツールを作ってください。
題材（自動車、医療機器、業務システム、設備など）に依存しない作りにします。

#前提
- 1ファイルで完結するHTML（外部ライブラリなし、オフラインで動く、サーバー不要）
- 日本語UI。ライト／ダーク対応。スマホ幅でも崩れない
- 正のデータは別にある（Excelなど）。HTMLは配って回答を集めるためのもの
- 要求の文は元データのまま載せる（要約・言い換えをしない）
- 題材固有の言葉をコードに直書きしない。画面の文言・階層名・選択肢はすべてCONFIGから出す

#設定（CONFIG）：ここを書き換えるだけで別の題材に使える
- title / lead：ツール名と、冒頭の依頼文
- levels：階層の定義（順番つきの配列。数は可変）
  例）[{key:"need", name:"利用者の要求"}, {key:"sys", name:"システム要求"}, {key:"alloc", name:"構成要素への要求"}, {key:"comp", name:"構成要素の要件"}]
- askLevel：担当者に確認してもらう階層（例：alloc）
- answerLevel：担当者自身の要件の階層（例：comp）
- attrs：要求の属性（例：機能／性能／制約／開発）
- categories：要求の区分（出所やサブシステム。色を自動で割り当てる）
- groups：回答する担当（チーム・部署）の一覧
- questions：確認項目の定義（可変）
  例）[{key:"ok", label:"要求は適切か", must:true, opts:["適切","直したい","対象外"]},
       {key:"vok", label:"目標値は適切か", must:true, opts:[...], skipIfNoValue:true},
       {key:"sync", label:"他の担当との整合が必要か", must:true, opts:["必要","不要"]}]
- labels：状態ラベル（例：仮設定／合意済）
- version / source：版と、元にしたデータの名前

#データ（DATA）
- nodes：id, level, text, value（目標値・任意）, attr, category, subject（主語＝構成要素）, groups（回答する担当・複数）, sources（出所）, memo, label, draft（AIの下書きならtrue）
- links：[親ID, 子ID, 状態, 変更者, 日時]
- 取り込み用のExcel書式（nodesシートとlinksシート）も一緒に定義し、ExcelからDATAのJSONを作る変換スクリプトを別に付ける
- IDの重複、存在しないIDへの線、階層が逆の線は、変換時に一覧で知らせる

#画面1：確認のお願い（回答フォーム）
- 依頼文、名前（必須）、担当（必須・選択）、保存ボタン
- ①自分の担当が答える要求：1行＝1要求。ID／文・値・主語／上位の要求（参考）／questionsの各項目／つながる自分の要件（任意・複数選択）／コメント（任意）。必須がそろった行は緑、途中は黄。文字での絞り込み、「未回答だけ」
- ②ほかの担当の要求：区分×主語ごとに折りたたむ。共通の要求を先頭。「自分に当てはまるか」を選んだら①と同じ項目に答える
- ③足りない要求の提案（必須。「無い」のチェックでも可）
- ④足りない自分の要件の追加（任意）
- ①から④へ飛ぶ固定ナビ（進み具合の件数つき）
- IDを押すと画面2でその箱を選ぶ。「戻る」で元の行に戻る

#画面2：つながりの図
- levelsの数だけ列を並べ、要求をカードで出す
- カードを押すと、上下にたどれるものだけ残し、曲線でつなぐ
- 右下に全文・出所・直接つながる上／下（押すと移動）。前へ／次へ、選択解除
- 列ごとの絞り込み（文字・区分・属性・ラベル・「上が無い」「下が無い」）
- 全体の絞り込み（区分・主語・担当）
- 下書き（draft）の箱と線は点線にして、確定したものと見分けられるようにする

#保存
- 押すと、同じ名前でCSVとHTMLをダウンロード（{title}_回答_{担当}_{名前}_{日時}）
- CSV：BOM付きUTF-8、1行＝1つの答え、列は固定。全員分を縦に積むだけで集計できる形。「種類」列で行を分ける（要求ごとの答え／ほかの要求の確認／つながり／要件の追加／提案）。questionsの項目は、定義した順に列にする
- HTML：今の回答を埋め込んで書き出す。開くと続きから書ける。「保存版」と表示する
- 未保存で閉じるときは警告。必須が残っていれば件数を出して確認する

#性能・品質
- 要求2,000件・線5,000本でも重くならない（選択肢や折りたたみの中身は開いたときに描画）
- エラー処理を入れる（データの不整合、読み込み失敗、保存失敗を画面に出す）
- コードのコメントは日本語、変数名・関数名は英語のキャメルケース。処理は小さい関数に分ける

#納品物
1. ツール本体のHTML（動作確認用に、自動車以外の題材のサンプルデータ30件ほどを入れる）
2. 取り込み用のExcel書式と、変換スクリプト
3. 使い方（設定の書き換え方、データの入れ替え方、回答の集め方）をページで

#進め方
作る前にCONFIGとDATAの形、画面構成、CSVの列のPlanを示してください。
わからない点は推測で埋めず、[要確認]をつけて質問してください。承認後に作ってください。
```

## 変数

このプロンプトには置き換え必須の変数はありません（題材は出来上がったツールの CONFIG で差し替える前提）。
必要に応じて次を書き換えます。

| 箇所 | 入れるもの | 例 |
|---|---|---|
| 納品物1のサンプル題材 | 動作確認に使う題材 | 「医療機器」「社内の経費精算システム」 |
| levels / questions の例 | 自分の現場の階層名・確認項目 | 「顧客要求／製品要求／モジュール要求／モジュール仕様」 |

## 使用例・コツ

- 「#進め方」で**作る前に Plan を出させ、[要確認] で質問させる**のが肝。一度で作らせるより手戻りが少ない。
- Plan を承認するときは、CSV の列の並びを特に確認する（集計の形が決まるため）。
- 規模感（2,000件・5,000本）を書いておくと、描画の遅延読み込みまで考えてくれる。
