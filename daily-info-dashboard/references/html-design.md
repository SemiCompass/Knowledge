# ダッシュボード HTML の設計

## 1. 原則

* **単一ファイル**。CSS（dashboard_style.css）と JS（dashboard_app.js）は build_dashboard.py が `<style>` `<script>` に埋め込む。
* **外部リソースを参照しない**。CDN・Webフォント・外部画像・アナリティクスは使わない（社外に通信しない／オフラインで開ける）。
  リンク（`<a href>`）は元システムへの移動用なので例外。
* **配色は CSS 変数だけで決める**。`:root` にライト、`:root[data-theme="dark"]` にダーク。色を直接書かない。
* **localStorage のキーは `dailyInfoDashboard.state.v1` 固定**。変えると過去の「済み」チェックが読めなくなる。
  中身の形を変えるときも、キーは変えずに読み込み側で古い形を受け付ける。
* JS が動かなくても内容は読める（HTML はサーバ側＝Python で描画し、JS は操作を足すだけ）。

## 2. 画面の構成（上から）

1. ヘッダー: 日付・氏名・生成時刻・エンジンのバージョン、テーマ切り替え
2. **今日の見立て**: 最大3文。各文の下に「根拠」リンク（ページ内の該当項目へ飛ぶ）
3. **取得状況**: ソースごとに 緑＝取得 n件 ／ 黄＝0件（理由） ／ 赤＝取得失敗（エラー）。警告もここ
4. 絞り込みバー（画面上部に固定）: キーワード、種類チップ、重点カテゴリーチップ、「済みを隠す」
5. 区分（各レコードは1区分だけに入る。上から順に判定）

| 区分 | 入る条件 |
|---|---|
| 本日決着 | `closed` が true |
| 今日の予定 | `kind = meeting` |
| 繰越 | `carried` が true |
| 他者待ち | `waiting_on` がある |
| 要対応 | `action` がある／期限が2日以内／自分担当のタスク・アラート／未読・フラグ・open のメール・チャット |
| 情報・更新 | 上記以外 |

画面の並び順は「今日の予定 → 要対応 → 他者待ち → 繰越 → 情報・更新 → 本日決着」。

## 3. 並べ替え（区分内）

点数の高い順。期限超過 +50、今日期限 +30、2日以内 +15、優先度 高 +20／中 +5、優先メンバー +15、
自分が担当・宛先・メンション +10、経過日数（最大+14）。会議は開始時刻順。

## 4. localStorage に保存するもの

```json
{ "done": { "<レコードID>": "2026-11-25" }, "folded": { "info": true }, "theme": "dark", "hideDone": true }
```

* `done` は60日を過ぎたものから自動で消す。
* 読み書きはすべて try/catch（保存できない環境でも表示は壊れない）。

## 5. 週次まとめ

* `weekly-<YYYY-Www>.md`: ローカル保存・Confluence 下書きの本文の元。
* `weekly-<YYYY-Www>.html`: 同じ CSS を使った閲覧用。
* `weekly-<YYYY-Www>.confluence.html`: 見出し・段落・箇条書き・表・リンクだけの簡易HTML（Confluence のストレージ形式に貼れる）。
* 内容は事実のみ: 概要（件数）、重点カテゴリー別件数、決着した項目、未決着の残り、新規、日々の見立て。

## 6. 変更するとき

* 色を変える → dashboard_style.css の変数だけ。
* 区分を変える → build_dashboard.py の `SECTIONS` と `section_of()`。
* 新しい操作を足す → dashboard_app.js。状態は既存の `state` オブジェクトに項目を足す（キーは変えない）。
* 変更したら assets/VERSION を上げる。
